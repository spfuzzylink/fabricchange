# Security

The initial release evaluates local input and does not mutate a cluster. Treat input as untrusted. A report is only as accurate as the recorded evidence or dependency map; it is not an authorization to operate equipment.

Do not put secrets or identifiable customer inventories into public issues. For a sensitive vulnerability, use GitHub private vulnerability reporting if enabled. If unavailable, open an issue asking the maintainer for a private reporting channel without disclosing the exploit or sensitive data. Only the latest experimental release receives fixes; no production support commitment is made.
